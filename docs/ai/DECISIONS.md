# Decisions

## 2026-09-05 — Maintain Windows source and validate on the destination PC

- Keep the SwiftUI/AppKit macOS app and the Electron Windows app in the same
  repository, with platform-specific window code. The Windows calculation model
  is based on the recovered JavaScript port from 小呆电脑's installed 1.0.0
  `app.asar`, aligned with the current Swift model rather than the old release.
- Windows 1.6.0 uses a normal opaque native window, preserving the dark/mint
  visual style and separate history panel. The old transparent shell, 80-pixel
  shadow margins and disabled GPU/sandbox flags are not carried forward. These
  were compatibility concerns in the old source, not a proven diagnosis of every
  failure the user experienced with 1.0.0.
- Preserve the original `D:\Awesome Calculator` installation, its profile and
  original shortcuts. The new installation is `D:\Awesome Calculator 1.6`, with
  a distinct application ID/profile. The existing desktop and Start-menu
  shortcuts now select the new version. Two uninstall entries can remain as a
  deliberate rollback option; do not remove the old installation automatically.
- Pin Electron 44.2.0, Electron Builder 26.15.3 and Playwright 1.63.0. Electron
  44 clipboard operations are asynchronous. IPC handlers must await clipboard
  reads/writes, and tests preserve all available ClipboardItem formats in memory.
- Correct native window bounds by measuring the requested/actual difference,
  using at most three passes. Windows fractional DPI caused both resize and
  position APIs to add pixels; naively feeding the returned height into the next
  operation made the window grow. Tests require unchanged outer height after
  repeated history toggles, at 125% and 150% scaling.
- Current display, AC/history separation, operator replacement, paste, editing,
  rounding and history limits are checked against 106 states generated by
  executing the actual current Swift model. Windows intentionally additionally
  accepts `。` as a decimal point, reports invalid clipboard input, and rejects
  clipboard expressions longer than 10,000 characters without partial evaluation.
- Build and install on Windows through the existing `windows-build` channel.
  Desktop tests run in the logged-in console session, not SSH's noninteractive
  session. A package file, build exit code or screenshot alone is insufficient
  evidence of a working installation.
- Project delivery is local build/install plus maintained source. GitHub
  publication and Windows certificate signing were not performed in this task.

## 2026-09-05 — Verify every existing launch entry during side-by-side replacement

- Desktop and Start-menu shortcuts did not cover the user's pinned taskbar
  entry. It still launched the preserved 1.0.0 app, whose AC behavior differs.
  Check pinned links, their application identities and the live process path
  before diagnosing a new source regression or declaring replacement complete.
- Repair the stale entry using the current installer's shortcut and keep its
  predecessor as a backup. The 1.6 runtime already has the required AC behavior;
  this follow-up changes launch state, tests and documentation without rebuilding
  or replacing an identical runtime.
